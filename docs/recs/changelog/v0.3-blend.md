# v0.3 Fewer, steadier interests

Date: 2026-10-20 · Status: default for the demo with Basic features

## Changes
- **At least 2 items per interest:** the number of clusters is `floor(saves / 2)`, capped at 3. Three saves no longer become three "interests".
- **Blend with overall taste:** relevance is half best-cluster match, half match to the overall taste vector (the v0.1 vector). This steadies single-interest users while keeping the multi-interest benefit.
- Menu default moved to v0.3.

## Measured
Basic features, 240 items, 4 personas × 30 simulated users, 5 rounds. Averaged over personas:

| Version | Avg precision | Last-round precision | Coverage | Redundancy (lower = more varied) |
|---|---|---|---|---|
| v0.1 | 75% | 55% | 74% | 0.47 |
| v0.2 | 71% | 58% | 84% | 0.24 |
| v0.3 | 73% | 62% | 88% | 0.33 |

- v0.3 recovers part of the single-interest loss (Art only 58% to 65%, Pixel look 57% to 70%).
- It gives back part of the multi-interest gain (Art + Music + Writing 91% to 87%).
- Net: a better balance, not a clean win. v0.1 still has the best raw precision on single-interest users.

## Things tried that did not help
- Merging nearby clusters (3 thresholds) and a more relaxed diversity weight for narrow tastes: no change.
- A higher blend (0.7): helped single-interest users more but cost multi-interest users more.

## Known weaknesses
- The remaining gap is mostly feature quality, not algorithm: the Basic features describe colour and layout, not content. Hence v0.4.
